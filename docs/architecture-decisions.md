# ADR (아키텍처 결정 기록) 개요

이 폴더는 자금팀 허브를 만들면서 내린 주요 설계 결정을 한 편씩 기록한 것입니다. 각 ADR은 **배경(왜) · 결정(무엇을) · 결과(무엇을 얻고 무엇을 감수했나) · 되돌릴 때** 를 담습니다.

되돌리려면 데이터 구조나 운영 방식을 손봐야 하는 결정만 여기에 둡니다. 화면 배치나 문구처럼 언제든 바꿀 수 있는 것은 [변경 이력](changelog.md)에만 남깁니다.

## 목록

| 번호 | 제목 | 상태 | 날짜 | 결정 한 줄 |
|---|---|---|---|---|
| [0010](adr/0010-server-side-history.md) | 수정 이력은 서버가 남긴다 | 채택 | 2026-09-09 | 화면이 보낸 값을 믿지 않고, 서버가 저장 전후 문서를 비교해 바뀐 항목만 `history` 표에 기록합니다. |
| [0009](adr/0009-manual-required-when-live.md) | 사용안내는 운영중 과제만 필수 | 채택 | 2026-09-09 | 사용안내(매뉴얼)는 개발 상태가 '운영중'일 때만 필수로 하고, 효과 지표는 모든 상태에서 필수로 둡니다. |
| [0008](adr/0008-savings-parity-with-group-ax.md) | 효과 지표는 그룹 AX 대시보드와 동일 기준 | 채택 | 2026-09-09 | 선택지·월 환산 공식·등급 기준을 그룹 대시보드에서 확인해 그대로 채택하고, 독립 검증기로 대조합니다. |
| [0007](adr/0007-attachments-on-filesystem.md) | 첨부파일은 서버 파일시스템에 | 채택 | 2026-09-09 | 첨부파일 본문은 DB에 넣지 않고 `server/uploads/` 폴더에 두고, 과제 문서는 목록만 가집니다. |
| [0006](adr/0006-scheduled-tasks-user-s4u.md) | 서버 PC 예약 작업은 로그인 계정 + S4U | 채택 | 2026-09-08 | 예약 작업을 SYSTEM 대신 로그인 계정 + LogonType S4U 로 등록하고, 스크립트는 평문으로 둡니다. |
| [0005](adr/0005-approval-only-for-starred.md) | ★ 과제는 승인 절차, 그 외는 담당자 직접 수정 | 채택 | 2026-09-07 | 그룹 대시보드 전달 대상(★)만 관리자 승인을 거치고, 그 외 과제는 담당자가 바로 저장합니다. |
| [0004](adr/0004-owner-by-account-email.md) | 담당자 권한은 계정(이메일)으로만 판정 | 채택 | 2026-09-04 | 담당자 이름 대신 `ownerEmail`(로그인 계정)로만 수정·삭제 권한을 판정합니다. |
| [0003](adr/0003-document-store-on-sqlite.md) | 문서형 저장소(SQLite 단일 표) | 채택 | 2026-09-07 | 컬렉션마다 표를 만들지 않고, `docs(coll, id, data JSON, version)` 한 표에 모든 문서를 담습니다. |
| [0002](adr/0002-single-frontend-with-adapter.md) | 화면 소스 한 벌, 연결 층만 교체 | 채택 | 2026-09-07 | 화면(`hub.html`)은 한 벌만 두고, 로그인·저장소 연결만 어댑터(`shim.js`·AUTH 층)로 갈아 끼웁니다. |
| [0001](adr/0001-artifact-to-onprem.md) | Artifact판에서 사내 서버판으로 | 채택 | 2026-09-07 | claude.ai Artifact판을 접고, FastAPI + SQLite 를 사내 서버 PC 에 올린 서버판으로 전환합니다. |

!!! note "상태 표기"
    전부 '채택'입니다. 뒤집힌 결정은 아직 없고, ADR-0001 의 서버판 자체는 전산팀의 Azure 이관 전까지의 중간 단계입니다.
