# 변경 이력

허브가 어떤 순서로 지금 모습이 됐는지 날짜 내림차순으로 정리한 것입니다. 각 버전마다 **쓰는 사람이 느끼는 변화**와 **코드·구조가 바뀐 점**을 한 줄씩 적었습니다.

설계 판단의 배경까지 알고 싶으면 [ADR 개요](architecture-decisions.md)를 함께 보세요. 버전 번호는 화면(`hub.html`)에 표시되는 번호이고, 사내 서버판은 v3.7 부터입니다.

!!! note "표기 규칙"
    실제 등록된 과제 이름·내용과 담당자 이름은 이 문서에 넣지 않습니다. 기능과 구조만 적습니다.

## 2026-09-09

작성 기준일입니다. 이날 하루에 v3.17 부터 v3.21 까지 올라갔고, 주제는 **그룹 AX 대시보드와 기준 맞추기**와 **서버 스스로 버티게 만들기** 두 가지였습니다.

### v3.22 — 과제별 개발 문서 사이트 링크

- **쓰는 사람**: 과제 상세 창에 「개발 문서 사이트(URL)」 칸(선택)이 생겼습니다. 바로 위 안내문이 개발 문서가 무엇인지, 왜 전산팀이 프로그램마다 요청하는지, 어떻게 만드는지(클로드 코드에 요청하는 문구)와 예시 사이트 2곳을 알려 줍니다. 값이 있으면 목록·메인 카드·상세 창에 `[문서 ↗]` 가 붙습니다.
- **기술**: `docsUrl` 필드(주소 형식 검사·`https://` 자동 보정), 엑셀 양식·업로드 머리글 「개발 문서(URL)」, 현황 xlsx AD열. 서버가 켜질 때 허브 자신의 과제에 이 문서 사이트 주소를 1회 기입합니다(수정 이력에 시스템으로 남음).

### v3.21 — 임시저장 확대 · 수정 이력 · 서버 감시

- **쓰는 사람**: 과제 상세 창에서 「수정 이력」을 펼치면 누가 언제 어떤 항목을 무엇으로 바꿨는지 최근 30건이 보입니다. 담당자가 직접 저장하는 과제에도 `[임시저장]` 버튼이 생겨, 필수 항목을 못 채워도 진행 상황을 남길 수 있습니다.
- **기술**: 서버의 문서 저장 함수가 이전·이후 문서를 비교해 바뀐 항목만 `history` 표에 기록(`GET /api/history/projects/{id}`). 서버 감시 스크립트(5분마다 응답 확인 → 죽으면 되살림)와 첨부파일 백업 스크립트를 예약 작업으로 추가. 담당자 직접 저장에도 필수 항목 검사를 적용 — 저장이 곧 팀 화면 반영인 경로는 모두 같은 규칙. → [ADR-0010](adr/0010-server-side-history.md)

### v3.20 — 사용안내는 '운영중' 과제만 필수

- **쓰는 사람**: 구상·개발중·중단 단계 과제는 사용안내를 비워 둬도 저장됩니다. 개발 상태를 '운영중'으로 바꾸면 그때 필수로 켜지고, 폼의 `*` 표시도 즉시 바뀝니다.
- **기술**: 항목 정의에 `reqWhen:"운영중"` 을 붙이고 필수 판정을 `fieldRequired()`·`manualNeeded()` 한 곳으로 모음. 목록 '보완필요' 배지는 운영중 과제의 사용안내만 셈. → [ADR-0009](adr/0009-manual-required-when-live.md)

### v3.19 — 효과 지표 입력칸 정리 · 임시저장

- **쓰는 사람**: 효과 지표 칸 높이가 통일돼 읽기 쉬워졌고, 관리자에게 필수 검사를 건너뛰는 `[임시저장]` 이 생겼습니다. 승인된 과제에 필수 항목이 비어 있으면 목록에 '보완필요' 로 표시됩니다.
- **기술**: 라벨 한 줄·입력칸 38px 고정, 임시저장 경로는 과제명만 검사.

### v3.18 · v3.18.1 — 효과 지표를 그룹 대시보드와 똑같이

- **쓰는 사람**: 효과 지표 입력이 그룹 대시보드의 '새 과제 등록' 창과 같은 배치가 됐습니다. 입력하는 동안 월 환산 시간·등급(대·중·소)·월 환산 금액·연 환산이 바로 보이고, 목록에 '월 절감' 열과 상단 합계 카드가 생겼습니다.
- **기술**: 빈도·주기 배수표와 월 환산 공식·등급 기준(50시간/10시간)을 대시보드 쪽에서 확인해 그대로 채택. 데이터는 `timeHours` → `timeValue` + `timeUnit` 으로 쪼개고 서버 기동 시 1회 변환. 상단 통계 줄 정렬 보정(v3.18.1). → [ADR-0008](adr/0008-savings-parity-with-group-ax.md)
- **함께**: 효과 지표가 대시보드와 정말 같은지 대조하는 독립 검증기(`verify_saving_parity.py`)를 추가 — 선택지·배수·등급, 1,512 조합 공식 비교, 그룹 양식 왕복 대조까지 읽기 전용으로 확인합니다.

### v3.17 · v3.17.1 — 그룹 AX 필수 항목 · 절감 7칸 · 첨부파일

- **쓰는 사람**: 과제에 사용안내(매뉴얼)를 적고, 링크와 첨부파일(20MB)을 붙일 수 있게 됐습니다. 절감 항목은 시간 절감 4칸 + 비용 절감 3칸으로 바뀌었고, 시간·비용 중 하나는 반드시 채워야 합니다.
- **기술**: 첨부는 `server/uploads/<id>.bin` + `<id>.json` 에 저장하고 API 3개(`POST/GET/DELETE /api/files`) 추가 — 로그인 필요·항상 내려받기. 서버 기동 시 `migrate_savings()` 가 옛 절감 키를 1회 변환(분→시간, 목록 밖 값은 비고에 `(구)`). 현황 엑셀 양식을 절감 8열 구조로 재편하고, 엑셀 업로드는 옛 머리글도 알아봅니다. → [ADR-0007](adr/0007-attachments-on-filesystem.md)

### 운영 도구

- **쓰는 사람**: 눈에 보이는 변화는 없습니다.
- **기술**: 서버 PC 원격 진단 워크플로우(읽기 전용, 수동 실행)와 데이터 점검 워크플로우(`server/check_data.py` — 가입·승인, 담당자 계정 연결, 필수 항목 충족 현황을 집계만 출력, 이메일은 가림)를 추가. 한글 경로·인라인 스크립트 깨짐 때문에 진단 스크립트는 BOM 붙인 `server/diag.ps1` 로 분리.

- **기술**: 회색·보라 토큰 제거(개발중 하늘색, 구상 살구, 회의 청록), 다크 모드 토큰도 같이 갱신. `planningNote` 를 엑셀 양식·CSV 열에 추가.

- **쓰는 사람**: `[현황 엑셀]` 로 팀 취합 양식 서식 그대로 된 xlsx 를 받고, `[그룹 양식]` 으로 그룹 대시보드 '등록된 과제 채우기' 양식을 받습니다.
- **기술**: `openpyxl` 템플릿 기반 `GET /api/export/status.xlsx` · `/api/export/group-fill.xlsx` 추가, 그룹 과제번호(`planningId`) 필드 신설(목록에서는 숨기고 상세 창 메타에만 표시).

### v3.11 · v3.12 — 사용 범위 '기타' · 계정 관리 표기

- **쓰는 사람**: 사용 범위에 없는 경우를 '기타' 로 골라 직접 적을 수 있습니다. 계정 관리 화면에 가입 대기 인원과 승인 계정 총원(관리자/일반/조회 전용)이 보입니다.
- **기술**: `scope` 를 선택 + 직접 입력 겸용(`selectEtc`) 형으로. 저장값이 선택지에 없으면 다시 열 때 '기타' + 그 문구로 표시.

### v3.7 — 사내 서버판(FastAPI + SQLite)

- **쓰는 사람**: claude.ai 화면 대신 사내 서버 주소로 접속합니다. 화면 구성과 데이터는 그대로입니다.
- **기술**: `server/` 신설 — FastAPI + SQLite 백엔드, 연결 층 `shim.js`, 정적 파일 빌드(`build_static.py`), Artifact 데이터 이관 스크립트. 화면은 `hub.html` 한 벌로 Artifact판·서버판 공용(로그인은 AUTH 층으로 분리). 데이터 파일과 백업은 git 제외. GitHub 비공개 저장소 연결. → [ADR-0001](adr/0001-artifact-to-onprem.md), [ADR-0002](adr/0002-single-frontend-with-adapter.md), [ADR-0003](adr/0003-document-store-on-sqlite.md)

### v3.8 — 바로가기 관리 · 개발 상태 4단계

- **쓰는 사람**: 메인 카드의 바로가기 링크를 화면에서 추가·수정·삭제합니다. 개발 상태가 구상 / 개발중 / 운영중 / 중단 4단계로 정리됐습니다.
- **기술**: `links` 컬렉션 신설(삭제는 관리자·본인 등록만). 폐지한 '시범운영' 은 화면에서 '개발중' 으로 읽는 별칭 처리.

### v3.9 · v3.10 — 확인창 일괄 적용 · 담당자 직접 수정

- **쓰는 사람**: 수정·삭제·승인처럼 되돌리기 어려운 동작 앞에 확인창이 뜹니다. ★ 표시가 없는 과제는 담당자가 승인을 기다리지 않고 바로 고치고 지울 수 있습니다.
- **기술**: 브라우저 기본 확인창 대신 자체 대화상자 `ask()` 로 통일(Artifact 샌드박스에서 기본 확인창이 무반응이었던 이력). 담당자 직접 수정 규칙을 화면(`freeEdit`)과 서버(`owner_free`) 양쪽에 같은 논리로 둠. → [ADR-0005](adr/0005-approval-only-for-starred.md)

Artifact판이 게시판에서 관리 도구로 커진 구간입니다(v2.2 → v3.6).

- **쓰는 사람**: 메인 화면이 업무 영역별로 나뉘고, 계정마다 권한이 3등급(관리자 / 일반 / 조회 전용)으로 갈렸습니다. 과제 등록·수정·삭제에 관리자 승인 절차가 생겼고, 취합 양식 엑셀을 올려 여러 과제를 한 번에 등록할 수 있게 됐습니다. 일정 화면에도 상세 정보와 업로드가 붙었습니다.
- **기술**: 담당자 권한 판정을 이름 대신 계정(`ownerEmail`) 기준으로 전환하고, 관리자용 `[담당자 계정 연결 실행]` 을 추가(이름이 1:1 로 일치할 때만 자동). 엑셀 머리글 정규식 매핑(취합 양식·옛 양식 호환), 쿨톤 블루 테마, 자체 확인창 도입. → [ADR-0004](adr/0004-owner-by-account-email.md)
