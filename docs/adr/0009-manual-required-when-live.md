# ADR-0009 · 사용안내는 운영중 과제만 필수

| 항목 | 내용 |
|---|---|
| 상태 | 채택 (2026-09-09, v3.20) |
| 결정 | 사용안내(매뉴얼)는 개발 상태가 '운영중'일 때만 필수(`reqWhen`)로 하고, 효과 지표는 모든 상태에서 필수로 둡니다. |

## 배경

그룹 AX 대시보드는 완료 과제에 **자료**(바로가기 · 사용안내 · 첨부파일 중 하나 이상)와 **효과 지표**를 요구합니다. 허브는 목적이 하나 더 있습니다 — 담당자가 바뀌어도 남이 그 프로그램을 쓸 수 있어야 한다는 **인수인계**입니다. 그래서 v3.17 에서 사용안내를 그냥 필수 항목으로 만들었습니다.

그런데 필수 검사가 엉뚱한 곳에서 걸렸습니다. 개발 상태가 '구상'·'개발중'·'중단'인 과제는 아직 프로그램이 없습니다. 실행 방법도 순서도 없는데 사용안내를 쓰라고 하면 담당자는 "아직 없음" 같은 문구로 칸만 채웁니다. 필수 항목이 형식적으로 통과되면 정작 운영중 과제의 빈 사용안내를 찾아내지 못합니다.

## 결정

필수 여부를 개발 상태에 따라 켜지는 **조건부 필수**로 바꿉니다.

| 항목 | 필수 조건 |
|---|---|
| 사용안내(`manual`) | 개발 상태가 **'운영중'** 일 때만 필수 |
| 효과 지표 | 모든 상태에서 필수 — 시간 절감 또는 비용 절감 중 한 세트(빈도·주기·값) |
| 링크(`url`) · 첨부(`files`) | 선택 |

구현은 판정 함수 한 곳에 모았고, 항목 정의에는 조건만 한 줄 붙습니다.

```js
const fieldRequired = (f, d) => !!f.req && (!f.reqWhen || (d || {}).status === f.reqWhen);
const manualNeeded  = d => (d || {}).status === "운영중";
// {k:"manual", …, req:1, reqWhen:"운영중", …}
```

이 한 곳의 판정을 세 군데가 같이 씁니다.

- 편집 폼의 `*` 표시 — 개발 상태를 바꾸면 즉시 켜지고 꺼집니다(`syncCondReq`)
- 저장(엄격) 검사와 관리자 승인 검사
- 목록의 '보완필요' 배지 — 운영중 과제의 사용안내만 셉니다(구상·개발중 과제는 효과 지표만 봄)

**임시저장** — 필수 항목을 아직 못 채웠어도 진행 상황을 남길 수 있어야 하므로, 검사를 건너뛰고 저장하는 `[임시저장]` 버튼을 둡니다. 과제명만 확인하고 저장하며, 빈 필수 항목은 목록에 '보완필요' 배지로 보입니다. 초안 저장·수정 초안 저장은 그 자체가 검사 없는 저장이라 별도 버튼이 없습니다.

## 결과 (장점 · 감수한 단점)

**장점**

- 필수 검사가 실제로 의미 있는 시점에만 걸립니다. '아직 없음' 같은 형식 답변이 사라집니다.
- '보완필요' 배지가 진짜 보완이 필요한 과제만 가리킵니다.
- 개발 상태를 '운영중'으로 바꾸는 순간 사용안내가 필수로 켜지므로, 운영 전환이 곧 인수인계 자료 작성 시점이 됩니다.
- 필수 판정이 한 함수에 모여 있어 다른 항목에도 `reqWhen` 한 줄로 같은 규칙을 적용할 수 있습니다.

**감수한 단점**

- 필수 항목이 상태에 따라 달라지므로 담당자에게 설명할 규칙이 하나 늘었습니다(폼의 `*` 표시가 즉시 바뀌게 해서 보완).
- '운영중'인데 사용안내가 비어 있으면 저장 자체가 막힙니다. 그래서 임시저장이 필요합니다.
- 임시저장을 남용하면 필수 항목이 계속 빈 채로 남습니다 — 목록 배지와 관리자 확인으로만 걸러집니다.

## 되돌릴 때

무조건 필수로 되돌리려면 항목 정의에서 `reqWhen:"운영중"` 을 지우면 됩니다(데이터 변경 없음). 반대로 다른 항목에도 같은 규칙을 주려면 `reqWhen` 을 한 줄 붙이면 되고, 판정·표시·검사가 함께 따라옵니다.
