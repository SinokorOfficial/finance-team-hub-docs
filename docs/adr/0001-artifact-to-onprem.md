# ADR-0001 · Artifact판에서 사내 서버판으로

| 항목 | 내용 |
|---|---|
| 상태 | 채택 (2026-09-07) |
| 결정 | claude.ai Artifact판을 접고, FastAPI + SQLite 로 만든 서버 프로그램을 사내 서버 PC 에 올려 팀이 사내망으로 접속합니다. |

## 배경

허브의 첫 버전(v1.0, 2026-08-31)은 claude.ai 의 Artifact 로 만들었습니다. Artifact 는 페이지 안에서 바로 쓸 수 있는 저장소(db)와 파일 내려주기(downloads) 기능을 제공해서, 서버를 준비하지 않고도 게시판·일정·계정 승인까지 만들 수 있었습니다. 실제로 v3.7 까지의 기능 대부분이 이 방식으로 완성됐습니다.

문제는 접속이었습니다. Artifact 를 열려면 보는 사람의 계정이 만든 사람과 같은 조직에 있어야 하는데, 팀원들의 계정 조직이 서로 달라 일부는 링크를 받아도 화면이 열리지 않았습니다. 데이터를 공용으로 쓰는 게시판인데 팀 전원이 못 들어오면 쓸 수가 없습니다.

또 하나는 이관 요구였습니다. 전산팀이 나중에 Azure 로 옮기기로 했는데, Artifact 안의 데이터는 그대로 들고 나오기 어려운 구조였습니다.

## 결정

사내 서버 PC 에 작은 서버 프로그램을 두는 방식으로 전환합니다.

- 서버: Python 3.12 · FastAPI · uvicorn (`server/app.py`), 포트 8002
- 데이터: SQLite 파일 하나(`server/hub.db`)
- 접속: 사내망 전용(사내망 주소는 사내 인수인계 문서 참조). 회사 이메일 도메인으로 가입 후 관리자 승인
- 기존 Artifact 데이터는 `server/import_snapshot.py` 로 한 번에 옮깁니다(계정 비밀번호 해시까지 그대로)

Artifact판은 폐기 방향이며, 화면 소스만 두 환경이 공유합니다([ADR-0002](0002-single-frontend-with-adapter.md)).

## 결과 (장점 · 감수한 단점)

**장점**

- 사내망에 있는 팀원 전원이 브라우저만으로 접속합니다. 계정 조직 문제가 사라졌습니다.
- 데이터가 파일 하나(+ 첨부 폴더)이므로 백업·이관이 폴더 복사로 끝납니다. Azure 이관도 같은 방식으로 옮길 수 있습니다.
- 권한·승인 규칙을 서버가 다시 검사할 수 있게 됐습니다(브라우저만 믿지 않음).

**감수한 단점**

- 서버 PC 가 꺼지면 허브도 멈춥니다 → 부팅 시 자동 실행 예약 작업과 감시 스크립트로 보완([ADR-0006](0006-scheduled-tasks-user-s4u.md), [서버 PC 운영](../operations.md)).
- 사내망 전용이라 외부에서는 접속할 수 없고, 통신은 아직 http 입니다(이관 시 https 검토).
- 배포·백업·감시 같은 운영 부담이 새로 생겼습니다 → GitHub Actions 자동 배포로 줄였습니다([배포](../deployment.md)).

## 되돌릴 때

되돌릴 대상은 아닙니다. 다음 단계는 Azure 이관이고, 그때는 `server` 폴더와 `hub.db`·`uploads` 를 옮겨 같은 명령으로 띄운 뒤 접속 주소와 로그인 방식(회사 계정)만 바꾸면 됩니다. 문서의 데이터 모델·API 장이 그 설계의 기초 자료입니다.
