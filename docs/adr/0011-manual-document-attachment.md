# ADR-0011 · 매뉴얼은 문서 파일 첨부까지 필수

| 항목 | 내용 |
|---|---|
| 상태 | 채택 (2026-09-09, v3.24) |
| 결정 | 개발 상태가 '운영중'인 과제는 사용안내 요약(글)과 **매뉴얼 문서 파일 첨부**를 모두 필수로 합니다. [ADR-0009](0009-manual-required-when-live.md) 의 "링크·첨부는 선택" 부분을 이 결정이 대체합니다. |

## 배경

허브의 사용안내는 여러 줄 글을 적는 칸입니다([ADR-0009](0009-manual-required-when-live.md)). 인수인계에는 그 편이 편합니다 — 목록을 열지 않고 상세 창에서 바로 읽히기 때문입니다.

그런데 허브 A절 항목의 1차 목적은 **그룹 대시보드 등록**입니다. 대시보드 쪽 기준을 다시 확인해 보니, 그 화면의 자료 모델은 이렇습니다.

| 대시보드 자료 구분 | 넣는 방법 |
|---|---|
| 바로가기 | 주소 |
| 사용안내 | **문서 파일 또는 주소** |
| 첨부파일 | **문서 파일** |

세 구분 모두 **파일이나 주소를 올리는 방식**이고, 쓰는 법을 **글로 적어 넣는 칸이 없습니다.** 과제를 '완료'로 넘길 때 대시보드가 요구하는 것은 자료 1건 이상이며, 자료가 하나도 없으면 그 과제는 '보완필요'로 남습니다.

즉 허브에서 사용안내 글만 채워도 대시보드 등록 요건은 채워지지 않습니다. 담당자는 허브에서 필수 검사를 통과했으니 끝났다고 생각하지만, 대시보드에 올릴 것이 없는 상태입니다. v3.17~v3.23 의 규칙에는 이 단계가 빠져 있었습니다.

## 결정

운영중 과제의 필수 항목을 두 개로 나눕니다.

| 항목 | 필수 조건 | 쓰이는 곳 |
|---|---|---|
| 사용안내 요약(`manual`) | 개발 상태가 '운영중'일 때 | 허브 상세 창에서 바로 읽는 요약 (3~5줄) |
| 매뉴얼 문서 첨부(`files` 1건 이상) | 개발 상태가 '운영중'일 때 | 대시보드 '사용안내' 자료로 그대로 올릴 문서 |
| 링크(`url`) · 개발 문서 사이트(`docsUrl`) | 선택 | 웹 프로그램 주소 · 인수인계용 개발 문서 |

첨부 항목에 조건부 필수를 붙이는 방식은 [ADR-0009](0009-manual-required-when-live.md) 의 `reqWhen` 을 그대로 씁니다. 다만 첨부는 값이 배열이라, 빈 배열(`[]`)이 "있음"으로 통과하지 않도록 판정 함수를 따로 둡니다.

```js
const manualDocOk = d => Array.isArray((d || {}).files) && d.files.length > 0;
// {k:"files", …, req:1, reqWhen:"운영중", t:"files"}
```

같은 판정을 네 곳이 씁니다.

- 편집 폼의 `*` 표시 — 개발 상태를 바꾸면 켜지고 꺼집니다(`syncCondReq`, 첨부 칸도 `data-reqwhen` 을 갖습니다)
- 저장(엄격) 검사 — 통과 못 하면 "매뉴얼 문서 파일을 올려 주세요" 안내와 함께 저장이 멈춥니다
- 관리자 승인 검사 — 빈 항목 목록에 '매뉴얼 문서 첨부'가 들어갑니다
- 목록의 '보완필요' 배지 — 운영중 과제에서 요약과 문서를 따로 셉니다

폼에는 왜 문서가 필요한지 적은 안내문(`MANUAL_NOTE`)을 첨부 칸 위에 둡니다. 대시보드에 글 칸이 없다는 사실, 형식은 자유(워드·PDF·한글), 화면 캡처를 넣어 3~5장이면 충분하다는 기준, 올린 파일을 대시보드에 그대로 다시 올린다는 흐름까지 한 문단입니다.

배열 값은 일반 필수 검사에서 제외합니다(`f.t !== "files"`). 빈 배열이 참으로 평가돼 검사가 통과되는 문제를 막기 위해서입니다.

## 결과 (장점 · 감수한 단점)

**장점**

- 허브에서 필수 검사를 통과한 운영중 과제는 대시보드 등록 요건도 함께 충족합니다. 두 시스템의 기준이 다시 일치합니다.
- 매뉴얼이 문서로 남습니다. 담당자가 바뀌어도 파일 하나로 전달되고, 첨부 백업 작업이 그 파일까지 함께 지킵니다.
- 요약(글)과 문서(파일)의 역할이 갈립니다. 요약은 허브에서 훑어보는 용도, 문서는 대시보드와 인수인계용입니다.

**감수한 단점**

- 운영중 과제 담당자는 문서를 한 번 만들어야 합니다. 글 몇 줄보다 손이 갑니다 — 안내문에 만드는 방법을 적어 부담을 줄였습니다.
- 이미 '운영중'으로 저장돼 있던 과제 중 첨부가 없는 건은 다음 저장 때 검사에 걸립니다. 당장 문서가 없으면 `[임시저장]`으로 두고 나중에 채우는 경로가 필요합니다.
- 첨부는 사내 서버판에서만 올릴 수 있어, 브라우저 단독판(Artifact)에서는 이 필수 항목을 채울 수 없습니다.

## 되돌릴 때

첨부를 다시 선택 항목으로 돌리려면 항목 정의에서 `req:1, reqWhen:"운영중"` 을 지우고, 저장 검사·승인 검사·`needFill()` 에서 `manualDocOk` 호출 세 줄을 지우면 됩니다. 데이터 구조는 그대로이므로 이미 올린 파일에는 영향이 없습니다.
