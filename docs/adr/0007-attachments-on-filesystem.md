# ADR-0007 · 첨부파일은 서버 파일시스템에

| 항목 | 내용 |
|---|---|
| 상태 | 채택 (2026-09-09, v3.17) |
| 결정 | 첨부파일 본문은 DB 에 넣지 않고 `server/uploads/` 폴더에 `<id>.bin` + `<id>.json`(메타)으로 저장하고, 과제 문서는 `files` 배열(목록)만 가집니다. |

## 배경

그룹 AX 대시보드는 완료 과제에 '자료'(바로가기 · 사용안내 · 첨부 중 하나 이상)를 요구합니다. 허브는 인수인계 자료를 모아 두는 것이 목적이므로, 매뉴얼 문서·프로그램 파일을 과제에 직접 붙일 수 있어야 했습니다. Artifact판에는 파일 저장 수단이 없었고, 서버판에서는 넣을 자리가 두 곳이었습니다.

| 방식 | 문제 |
|---|---|
| `hub.db` 안에 BLOB 으로 | 문서형 저장소가 문서 JSON 을 통째로 주고받는 구조라([ADR-0003](0003-document-store-on-sqlite.md)) 파일 본문이 목록 조회에까지 실려 옴. DB 가 커져 백업·복구도 무거워짐 |
| 파일시스템 폴더에 | DB 백업과 첨부 백업을 따로 관리해야 함 |

## 결정

파일시스템에 둡니다.

- 본문: `server/uploads/<id>.bin` (`id` 는 16자리 16진수)
- 메타: `server/uploads/<id>.json` — 원래 파일 이름, 크기, 올린 사람 이름·계정, 올린 시각
- 과제 문서: `files: [{id, name, size, by, at}]` 배열만 가짐

| 경로 | 규칙 |
|---|---|
| `POST /api/files?name=…` | 본문 = 파일 그대로. 20MB 한도(헤더와 실제 크기 둘 다 검사). 조회 전용 계정 불가 |
| `GET /api/files/{id}` | 로그인 필요. `Content-Disposition: attachment` + `application/octet-stream` 으로 **항상 내려받기** |
| `DELETE /api/files/{id}` | 올린 사람 또는 관리자만 |

!!! warning "항상 내려받기로 내려주는 이유"
    올린 HTML 파일이 브라우저에서 그대로 실행되면 허브와 같은 주소에서 남의 스크립트가 도는 셈이 됩니다. 그래서 파일 종류를 따지지 않고 내려받기로만 응답합니다.

업로드·삭제는 `audit` 표에 기록합니다. 과제의 `files` 목록에서 뺀 파일은 서버에 남을 수 있습니다 — 승인 전 원본이 그 파일을 아직 참조할 수 있어 지우지 않습니다.

**백업은 별도 작업입니다.** `uploads` 폴더는 git·자동 배포·DB 백업 어디에도 포함되지 않습니다. 그래서 2026-09-09 에 `server/backup_uploads.ps1`(매일 23:20, `backup/uploads` 미러 + 날짜별 zip 14일 보관)을 별도 예약 작업으로 추가했습니다.

## 결과 (장점 · 감수한 단점)

**장점**

- `hub.db` 가 작게 유지되고, 목록 조회에 파일 본문이 실리지 않습니다.
- 파일이 폴더에 그대로 있어 필요할 때 직접 꺼낼 수 있고, 이관도 폴더 복사입니다.
- 파일 본문과 권한 판정이 분리돼서, 문서 저장 규칙([ADR-0005](0005-approval-only-for-starred.md))을 건드리지 않고 첨부를 붙였습니다.

**감수한 단점**

- 백업 대상이 두 개(`hub.db` + `uploads`)가 됐습니다. 백업 작업을 하나 더 운영해야 합니다.
- 목록에서 뺀 파일이 폴더에 남습니다. 오래 쓰면 고아 파일 정리가 필요합니다 — 현재는 자동 정리를 넣지 않았습니다.
- 문서와 파일이 원자적으로 함께 저장되지 않습니다(업로드 성공 후 문서 저장이 실패하면 파일만 남음).

## 되돌릴 때

Azure 로 이관하면 첨부는 Blob 저장소로 옮기는 것이 자연스럽습니다. 과제 문서의 `files` 배열은 `id`·`name`·`size` 만 들고 있으므로, `id` 를 Blob 키로 바꾸고 세 엔드포인트만 다시 쓰면 화면은 그대로 씁니다.
