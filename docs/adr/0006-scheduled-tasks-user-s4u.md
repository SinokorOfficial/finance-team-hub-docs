# ADR-0006 · 서버 PC 예약 작업은 로그인 계정 + S4U

| 항목 | 내용 |
|---|---|
| 상태 | 채택 (2026-09-08) |
| 결정 | 서버 PC 의 예약 작업은 SYSTEM 대신 **로그인 계정 SID + LogonType S4U** 로 XML 등록하고, 실행되는 스크립트는 평문 `.ps1`/`.bat` 로 둡니다. |

## 배경

허브 서버는 서버 PC 가 부팅되면 저절로 떠 있어야 합니다. 그래서 처음에는 작업 스케줄러에 SYSTEM 계정 + 부팅 트리거로 서버 실행 배치를 등록했습니다.

2026-09-08 설치 중에, 등록한 작업 두 개(서버 자동 실행·DB 백업)가 **1분 안에 조용히 사라지는** 현상을 확인했습니다. 삭제 이벤트도 남지 않았고, 같은 PC 에서 살아 있는 다른 작업들은 전부 로그인 계정 소유였습니다. 사내 보안 제품 정책상 'SYSTEM + 부팅 트리거 + 배치 파일' 조합이 허용되지 않는 것으로 판단했습니다. 같은 정책으로 명령을 base64 로 인코딩해 넘기는 PowerShell 실행 방식도 강제 종료됐습니다.

함정이 하나 더 있었습니다. `schtasks` 로 만든 작업은 기본값이 "3일 이상 실행되면 중지"라서, 상시 떠 있어야 하는 서버가 72시간 뒤에 저절로 내려갑니다.

## 결정

예약 작업 등록 방식을 다음과 같이 고정합니다.

| 항목 | 값 | 이유 |
|---|---|---|
| 실행 계정 | 서버 PC 의 로그인 계정 SID | 보안 제품 정책에 맞는 조합 |
| `LogonType` | `S4U` | 비밀번호를 저장하지 않고도 로그온 없이 실행됨 |
| `RunLevel` | `HighestAvailable` | 예약 작업 제어·포트 사용에 필요 |
| 등록 방법 | `schtasks /create /xml` (XML 은 **UTF-16LE**) | 명령줄 옵션만으로는 S4U 를 지정할 수 없음 |
| `ExecutionTimeLimit` | `PT0S` (제한 없음) | 기본 3일 제한 해제 |
| `RestartOnFailure` | 1분 간격 3회 | 기동 실패 시 자동 재시도 |
| 스크립트 | 평문 `.ps1` / `.bat` | 인코딩된 명령줄은 정책상 사용하지 않음 |

XML 은 템플릿(`usb/tools/task_*.xml`)으로 두고 설치 스크립트가 서버 경로와 계정 SID 를 치환해 등록합니다. 2026-09-09 에 추가한 감시·첨부 백업 작업도 같은 방식(`server/tools/register_tasks.ps1`)입니다.

파이썬 실행기도 함께 못 박았습니다 — `C:\Program Files` 아래의 실물 `python.exe`(3.12/3.13)만 인정하고, 사용자 `AppData` 의 런처는 다른 계정 컨텍스트에서 런타임을 못 찾아 배제합니다. 서버는 `pythonw` 대신 `python.exe` + 로그 파일 리다이렉트로 띄웁니다(표준 출력이 없으면 uvicorn 이 기동 직후 종료).

!!! warning "등록 후 확인"
    실패가 조용하기 때문에, 등록하고 2분쯤 뒤에 작업이 그대로 남아 있는지 다시 확인해야 합니다. 설치 스크립트도 20초 후 잔존 여부를 재확인합니다.

## 결과 (장점 · 감수한 단점)

**장점**

- 부팅 시 자동 실행·일일 백업·5분 감시·첨부 백업이 모두 안정적으로 남아 있습니다.
- 비밀번호를 어디에도 저장하지 않습니다(S4U).
- 스크립트가 평문이라 담당자가 내용을 그대로 읽고 고칠 수 있습니다.

**감수한 단점**

- 작업이 특정 계정에 묶입니다. 로그인 계정이 바뀌면 SID 가 달라져 다시 등록해야 합니다(`tools\예약작업_재등록.bat`).
- XML 등록이라 한 줄 명령보다 손이 가고, 인코딩(UTF-16LE)을 틀리면 등록이 실패합니다.
- 자동 배포는 스크립트 파일만 갱신하므로, 새 예약 작업은 서버 PC 에서 등록 배치를 한 번 직접 실행해야 합니다.

## 되돌릴 때

리눅스 환경으로 이관하면 이 결정 자체가 필요 없어집니다(컨테이너 재시작 정책으로 대체). Windows 를 계속 쓰면서 방식을 바꾸려면, 바꾼 뒤 작업이 실제로 남아 있는지 며칠 지켜본 다음 판단해야 합니다.
